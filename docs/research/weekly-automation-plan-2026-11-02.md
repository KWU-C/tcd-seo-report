## 1. Dot から集計値を受け取る仕組み

### 1-1. 保存先

- **新しいスプレッドシート「reports_v2 週次問い合わせ集計」**を作り、タブ `weekly` に1週1行で記録する。
- 既存の「問い合わせ一覧」（商談・受注の台帳）とは分ける。役割が違い、一覧は送信総数の代わりにならないため。
- 共有範囲は運用担当者とレポートを実行するアカウントだけ。件数のみを記録し、氏名・会社名・メールアドレス・本文は書かない。
- スプレッドシート ID は `.env`（`INQUIRY_SHEET_ID`）に置き、Git には入れない。

### 1-2. データ形式（タブ `weekly`）

1行目は見出し（下表の列名をそのまま入れる。並び順を変えても列名で読む）。2行目以降が1週1行。

| 列名 | 内容 | 入力ルール |
|---|---|---|
| `week_start` | 週の開始日（月曜） | `YYYY-MM-DD`。月曜でなければ不整合扱い |
| `week_end` | 週の終了日（日曜） | `week_start` の6日後 |
| `status` | `確定` または `集計中` | `確定` の行だけを件数として使う |
| `general_total` | 一般問い合わせフォームの実送信数（返信を除く） | 0以上の整数 |
| `project_consultation` | うち案件相談 | 0以上の整数 |
| `sales_solicitation` | うち売り込み・提携勧誘 | 0以上の整数 |
| `other` | うちその他（要確認を含む） | 0以上の整数 |
| `other_needs_review` | その他のうち要確認 | 0以上、`other` 以下 |
| `recruiting_form` | 専用採用フォームの送信数（別集計） | 0以上の整数 |
| `excluded_replies` | 除外した返信メールの数（参考） | 任意 |
| `confirmed_by` | 集計した人（`Dot` など） | 任意（個人名を避けたい場合は役割名） |
| `confirmed_at` | 確定日時 | `YYYY-MM-DD HH:MM`（JST） |
| `note` | 確認方法などの注記 | 任意。個人情報は書かない |

- 検査（現行の `inquiries.yaml` と同じ）: `general_total = project_consultation + sales_solicitation + other`、件数はすべて0以上の整数、`other_needs_review ≤ other`、同じ週の行は1つだけ。
- スプレッドシート側にも入力規則を付ける（`status` はプルダウン、件数は0以上の整数、日付は日付形式）。見出し行は保護する。
- 訂正は、その週の行を書き換える（行を追加しない）。次回の生成時に反映される。

### 1-3. Dot への指示（追加する手順）

毎週月曜 8:45 までに（締め時刻は要決定、4章）:

1. Gmail の問い合わせ通知を、前週の月曜 0:00〜日曜 24:00（日本時間、受信日時）の範囲で確認する。
2. 返信メールを除き、本文で「案件相談／売り込み・提携勧誘／その他（判断が難しいものは要確認）」に分類する。専用採用フォームは別に数える。
3. スプレッドシートの `weekly` タブに1行を書く。Dot が直接書き込めない場合は、次の1行（タブ区切り）を出力し、担当者が貼り付ける。

   ```
   2026-11-02	2026-11-08	確定	10	1	7	2	0	1	6	Dot	2026-11-09 08:30	通知メールから確認。サーバー側の未着分は未確認
   ```

4. 集計が終わっていない場合は、行を書かないか `status` を `集計中` にする（0件で埋めない）。

### 1-4. reports_v2 での読み込み

- **取得**: Google Sheets API の `spreadsheets.values.get`（範囲 `weekly!A1:M`、書式なしの値）。権限は `spreadsheets.readonly`。既存のトークンには追加せず、別ファイル `token_sheets.pickle` に保存する（GA4 と同じ方式、gitignore に追加）。
- **タイミング**: パイプラインの取得工程（GSC・AIO・GA4 と同じ段階）で読み、取得した行を処理済みデータ（`data_v2/processed/<週>/inquiries_snapshot.json`、Git対象外）に保存する。分析・生成はこの保存済みデータだけを使うので、同じ週を作り直しても結果が変わらない。
- **後から集計が届いた場合**: `python -m src_v2.inquiries --week 2026-11-02` で再取得し、レポートを作り直せる（自動の再送はしない。2章の二重配信防止に従う）。

### 1-5. 週ごとの値の決め方（優先順）

| 状況 | レポートの表示 | 累計への算入 |
|---|---|---|
| `inquiries.yaml` に手入力の値がある | 件数（確定・手入力） | する |
| スプレッドシートに `確定` の行があり、検査を通る | 件数（確定・Dot） | する |
| 行がない、または `集計中` | **未集計** | しない |
| 行はあるが検査に通らない | **未集計（集計値に不整合）** | しない |
| スプレッドシートを取得できない（権限・通信） | **未集計（取得失敗）** | しない |

- どの場合も**レポート生成は止めない**。未集計を0件として扱わない。
- 不整合・取得失敗は、担当者（kawauchi@tcd.jp）にエラー通知を送る（3章）。
- 手入力とスプレッドシートの両方に値があり、内容が違う場合は手入力を使い、通知で知らせる。
- 現行の `inquiries.yaml` は、手入力用（スプレッドシートが使えないときの代替・訂正）として残す。手入力に不整合があるときは、現行どおり生成時にエラーで止める（リポジトリ内のファイルなので、その場で直せるため）。

### 1-6. 4週・12週累計

- 月〜日の週が連続してすべて「確定」の場合だけ、確定値として表示する。1週でも未集計なら「未確定（4週中3週確定）」と表示する（現行仕様）。
- 初回から4週・12週累計を出したい場合は、Dot に過去分（月〜日単位）をさかのぼって集計してもらう（任意。12週分なら 8/10〜11/01）。

### 1-7. 既存の 10/18〜10/24 の扱い（期間重複の解消）

- 値は変えずに保持する。`inquiries.yaml` の該当週に `scheme: legacy_sun_sat`（旧方式・日〜土）を追記する。
- 期間重複の検査は、同じ方式どうしでだけ行う。旧方式の週は、新方式（月〜日）の4週・12週累計に入れない。
- 新方式の最初の週と重なる 10/19〜10/25 は、必要なら Dot が月〜日で集計し直す（旧方式の記録はそのまま残す）。
- 旧方式の週は、`config_v2/inquiries.yaml` と、過去に送ったレポートにだけ残る。新しいレポートには表示しない。

### 1-8. レポートの表示

- ②の見出しに期間と出典を入れる: 「② 問い合わせ実績（10/26〜11/01、Dot集計）」。
- 「未入力」の表記を「未集計」に変える。注記は「当週の問い合わせは未集計（0件ではない）」。
- 冒頭の対象期間欄にデータごとの期間を並べる: 「アクセス・問い合わせ: 10/26(月)〜11/01(日) ／ 検索順位: 10/24(土)〜10/30(金)（Search Consoleの確定済み最新7日） ／ AIO: 11/02 09:0x 観測」。

### P1. 集計期間の再設計（1〜1.5日）

- `src_v2/pipeline.py` の `get_weekly_period()` を置き換え、期間を3種類にする。
  - `report_week`: 前週の月〜日（JST、GA4・問い合わせ用）。実行日ではなく、指定週または「直近の完了した週」から決める。
  - `gsc_period`: Search Console の `firstIncompleteDate` の前日を末日とする7日間。`gsc_comparison_period`: その直前の7日間。
  - `aio_observed_at`: 観測日時。
- `config_v2/pipeline.yaml` の `gsc.data_cutoff.mode` に `auto` を実装する（`fixed` は残す）。確定が遅れて金曜が未確定のときは自動で前にずらし、注記を出す。
- フォルダ名は `report_week` で決める（例 `2026-11-02_2026-11-08`）。同じ週は何度実行しても同じフォルダになる。
- `analysis/summary.py` の前週データの探し方を、フォルダ名ではなく「前の report_week」で探すように変える。移行の1週目は、旧方式の最後のフォルダ（`2026-10-24_2026-10-30`）を前週として扱い、GSC の前週比が途切れないようにする。
- GA4: 当週は「速報値（日曜分は処理中の可能性）」と表示。翌週に同じ期間を比較期間として取り直したときの差をログに残す。
- 表示: 冒頭の対象期間欄と、③④の見出しに各期間を明記する。
- 既存の `reports_v2/` と `data_v2/processed/` のフォルダは変更・削除しない。

### P2. 問い合わせのスプレッドシート連携（1日）

- `src_v2/fetch_inquiries.py`: Sheets API で取得し、列名で読み、行ごとに検査して「確定／未集計／不整合」を付ける。取得失敗は例外で止めず「取得失敗」として返す。
- `src_v2/auth.py`: `spreadsheets.readonly` 用の `get_sheets_credentials()`（`token_sheets.pickle`）。
- `config_loader.load_inquiries()`: `scheme` に対応し、重複検査を同じ方式どうしに限る。
- `view_model._build_inquiries()`: 1-5 の優先順と表示（未集計・不整合・取得失敗）、月〜日での累計。
- `inquiries.yaml`: 10/18〜10/24 に `scheme: legacy_sun_sat` を追記する（値は変えない）。
- テスト: 未集計・集計中・不整合・取得失敗・手入力優先・旧方式の除外・累計の連続性。

### P3. 実行制御・二重配信防止・エラー通知（1日）

- `scripts/weekly_report.sh` を作り直す。
  - 引数 `--week YYYY-MM-DD`（省略時は直近の完了した週）、`--dry-run`（送信しない。`preview_v2/` に出力）。
  - ロック: `mkdir` によるロックで同時実行を防ぐ（取れなければ終了）。
  - 送信済み台帳: `state/sent/<週>.json`（送信日時・宛先・GmailメッセージID）。台帳がある週は送らない。再送は `--force-resend` を明示したときだけ。`state/` は Git 対象外。
- `src_v2/report/send.py`: `--report-dir` を必須にし、「最新のフォルダ」の自動選択をやめる（送る週の取り違えを防ぐ）。送信成功時に台帳を書く。
- エラー通知 `src_v2/notify.py`（既存の `gmail.send` 権限を使う）:
  - 失敗通知（取得失敗・データ品質fail・送信失敗）: 工程名とログ末尾を kawauchi@tcd.jp に送る。
  - 配信後の確認通知（警告がある場合のみ）: 問い合わせ未集計・不整合・取得失敗、AIO判定不可、GSC期間のずれ、GA4取得失敗。
  - 月曜12:00の時点で未送信なら、未送信通知。
  - 通知の送信にも失敗した場合は、ログと macOS の通知センターに残す。

- `pmset repeat wakeorpoweron M 08:55:00` は、有効化のときにユーザーが実行する（管理者権限）。

## 3. 決めておくこと

1. **Dot の書き込み方法**: Dot がスプレッドシートに直接書けるか。書けない場合は、Dot が出力した1行を担当者が貼り付ける。
2. **Dot の締め時刻**: レポートは月曜 9:00 に生成する。それまでに確定していない週は「未集計」で配信される。締めを月曜 8:45 にするか、レポートの開始を遅らせる（例 10:00）か。
3. **スプレッドシートの所有者**と、読み取りを認可するアカウント（現在のレポート実行アカウントと同じか）。
4. **過去分の集計**: 4週・12週累計を早く出すため、Dot が過去の週を月〜日でさかのぼって集計するか（任意）。
