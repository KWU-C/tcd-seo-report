# 新版Looker⑤ 独立継続更新

既存の収集・分析・メール送信を呼ばず、完成済み `reports_v2/*/report.json` の
`appendix.initiatives` を表示用に変換する。既存の週次スクリプト、launchd、OAuthトークンは変更しない。
②の候補抽出、③のAIO本接続はこの処理に含まない。

## 保存・人判断の保護

- JSON生成時刻、取込時刻、GSC対象期間、比較期間、施策ID、入力SHA256、原判定、原根拠、
  元出力の14/28日等の比較窓をSQLiteに追記。入力の再生成は別履歴、同じ入力は再実行しても増えない。
- 既存の「施策評価」A:Pと同じ列へ新規行だけを追加する。既存行・人の評価G:I・元改善21件・監査61項目は書き換えない。
- 人が過去の評価行に記録した判断はその行に残す。新しい観測行に人の過去判断をコピーして確定済みにしない。
- 人確定優先度を読み書きしない。未取得はゼロにしない。元出力の対象URL空欄は未設定。
- 旧「比較対照と異なる減少」は表示だけ「比較対照を下回る変化」へ変換。元文言は履歴に保持。
- 14/28日評価を独自に再計算しない。元週次が生成した最新の比較と判定を保存する。
  週次出力にI01/I03がない現状では、両件の改修後評価は未接続のまま。元台帳の日付を移しただけで評価済みにしない。
- 自動追記行は `AUTO-` の評価IDで識別。初期27件を削除・上書きしないため、同一施策の時点違いが並ぶ。
  これは施策数の増加ではなく観測履歴。現在のLooker表は本番反映日順で、最新行だけの表示ではない。

## 実行

```sh
python -m looker_sync.weekly --reports-root reports_v2 --state-dir /別の場所/TCDLookerSync
```

既定では外部書込なし。保存済みJSONから `history.sqlite3`、`machine_history.json`、`status.json` を作る。
publishは `--publish --spreadsheet-id <新版専用台帳ID>` を明示する。

Google Sheetsへの書込は独立したADC認証を使う。既存の `token.pickle`、`token_sheets.pickle`、
GA4トークンを読み替えたり、権限を追加して再発行したりしない。認証がなければ自動ログインせず失敗する。
新しい書込権限の認可・サービスアカウントへの共有は、利用者が対象・権限を確認してから行う。
実機の認証設定、ジョブ登録、無人更新は開発環境での試験と別の完了条件である。

## 定期実行

`scripts/launchd/com.tcd.looker-sync.plist.example` は毎日13:30の独立ジョブ例（未登録）。
実機でPythonパス・参照ディレクトリ・独立認証・ログ先を確認してから配置する。
既存週次ジョブから呼ばない。独立プロセスの失敗が既存の収集・配信終了コードを変える構造はない。
自動再試行は翌日の独立実行。API書込の応答が失われても、次回に台帳IDを読み直し追記重複を避ける。
同じstate-dirの並行実行はロックで防ぐ。複数マシン／複数state-dirからの同時書込は運用対象外。

## 失敗時

- 不完全JSON、未知スキーマ、品質fail、重複施策IDはそのファイルを除外し警告。次回に再確認する。
- 書込失敗でもSQLite履歴は残り、既存台帳も週次出力も削除しない。
- status.jsonには最終確認時刻、最新の元出力時刻、履歴件数、追記件数、失敗状態を記録する。
- メール送信・本番サイトの変更は行わない。追加の失敗通知は未接続。
- ⑤の既存初期取込説明は、自動運用開始を実機で確認してから変更する。稼働前に自動更新済みと表示しない。

## 検証

```sh
python -m pytest tests_v2/test_looker_sync.py
```

実機稼働の完了条件：同じ出力で新規0件、同じ週の再生成で別履歴、人が入力した評価を維持、
API失敗後の再実行で重複なし、既存週次の送信と独立、Lookerで追加行と観測日時を確認すること。
本文・引用等を持つAIO原本は本モジュールから接続・評価しない。
